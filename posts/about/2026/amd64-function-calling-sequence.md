## 3.2 函数调用约定

本节描述标准函数调用约定，包括栈帧布局、寄存器使用、参数传递等。

标准调用约定要求仅适用于全局函数。其他编译单元不可达的局部函数可以使用不同的约定。尽管如此，建议所有函数在可能的情况下都使用标准调用约定。

### 3.2.1 寄存器

AMD64 架构提供 16 个通用 64 位寄存器。此外，该架构还提供 16 个 SSE 寄存器，每个 128 位宽，以及 8 个 x87 浮点寄存器，每个 80 位宽。每个 x87 浮点寄存器在 MMX/3DNow! 模式下可作为 64 位寄存器引用。所有这些寄存器对于给定线程中活动的所有过程都是全局的。

Intel AVX（高级向量扩展）提供 16 个 256 位宽的 AVX 寄存器（`%ymm0`-`%ymm15`）。`%ymm0`-`%ymm15` 的低 128 位与相应的 128 位 SSE 寄存器（`%xmm0`-`%xmm15`）别名。Intel AVX-512 提供 32 个 512 位宽的 SIMD 寄存器（`%zmm0`-`%zmm31`）。`%zmm0`-`%zmm31` 的低 128 位与相应的 128 位 SSE 寄存器（`%xmm0`-`%xmm31`）别名。`%zmm0`-`%zmm31` 的低 256 位与相应的 256 位 AVX 寄存器（`%ymm0`-`%ymm31`）别名。出于参数传递和函数返回的目的，`%xmmN`、`%ymmN` 和 `%zmmN` 指的是同一寄存器。同一时刻只能使用其中之一。我们使用**向量寄存器**来指代 SSE、AVX 或 AVX-512 寄存器。此外，Intel AVX-512 还提供 8 个向量掩码寄存器（`%k0`-`%k7`），每个 64 位宽。

Intel 高级矩阵扩展（Intel AMX）是一种编程范式，由两部分组成：一组表示来自更大二维内存图像的子数组的二维寄存器（tile），以及能够对 tile 进行操作的加速器。Intel AMX 实现的能力通过调色板（palette）枚举。支持两种调色板：调色板 0 表示初始化状态，调色板 1 由 8 个 tile 寄存器（`%tmm0`-`%tmm7`）组成，每个最大 1KB 大小，由一个 tile 控制寄存器控制。

Intel APX（高级性能扩展）提供 16 个通用 64 位寄存器（`%r16`-`%r31`）。

本小节讨论每个寄存器的用法。寄存器 `%rbp`、`%rbx` 和 `%r12` 到 `%r15` “属于”调用函数，被调用函数需要保存它们的值。换句话说，被调用函数必须为其调用者保存这些寄存器的值。其余寄存器“属于”被调用函数。如果调用函数希望在函数调用之间保存此类寄存器的值，则必须将其保存在自己的局部存储中。

> 注意，与 Intel386 ABI 相反，`%rdi` 和 `%rsi` 属于被调用函数，而非调用者。

进入函数时 CPU 应处于 x87 模式。因此，每个使用 MMX 寄存器的函数在使用 MMX 寄存器后、返回或调用另一个函数之前，必须发出 `emms` 或 `femms` 指令。

`%rFLAGS` 寄存器中的方向标志 DF 必须在函数进入和返回时清零（设置为“正向”方向）。其他用户标志在标准调用序列中没有指定作用，也不在调用之间保存。

MXCSR 寄存器的控制位由被调用者保存（在调用之间保留），而状态位由调用者保存（不保留）。x87 状态字寄存器由调用者保存，而 x87 控制字由被调用者保存。

### 3.2.2 栈帧

除寄存器外，每个函数在运行时栈上都有一个帧。该栈从高地址向低地址增长。图 3.3 显示了栈帧布局。

输入参数区域的末端必须对齐到 16（如果通过栈传递 `__m256` 或 `__m512`，则为 32 或 64）字节边界。

换句话说，在执行 `call` 指令之前，栈需要对齐到 16（32 或 64）字节。一旦控制转移到函数入口点，即返回地址被压栈后，`%rsp` 指向返回地址，且 `(%rsp+8)` 的值是 16（32 或 64）的倍数。

`%rsp` 指向位置之外的 128 字节区域被视为保留区域，信号或中断处理程序不得修改它。因此，函数可以将此区域用于在函数调用之间不需要的临时数据。特别是，叶函数可以将此区域用作其整个栈帧，而无需在序言和尾声调整栈指针。此区域称为**红区（red zone）**。

### 3.2.3 参数传递

参数值计算完成后，它们被放置在寄存器中或压入栈中。值的传递方式在以下小节中描述。

#### 定义

我们首先定义若干类别来对参数进行分类。这些类别对应于 AMD64 寄存器类别，定义如下：

- **INTEGER**：该类别包含可放入一个通用寄存器的整型。
- **SSE**：该类别包含可放入向量寄存器的类型。
- **SSEUP**：该类别包含可放入向量寄存器并可在其高字节中传递和返回的类型。
- **X87、X87UP**：这些类别包含将通过 x87 FPU 返回的类型。
- **COMPLEX_X87**：该类别包含将通过 x87 FPU 返回的类型。
- **NO_CLASS**：该类别在算法中用作初始化器。它将用于填充以及空结构和联合。
- **MEMORY**：该类别包含将通过栈在内存中传递和返回的类型。

#### 分类

每个参数的大小向上取整到**八字节**¹⁴。

基本类型被赋予其自然类别：

- 类型为（有符号和无符号）`_Bool`、`char`、`short`、`int`、`long`、`long long` 以及指针的参数属于 **INTEGER** 类别。
- 类型为 `_Float16`、`float`、`double`、`_Decimal64` 和 `__m64` 的参数属于 **SSE** 类别。
- 类型为 `__float128`、`_Decimal128` 和 `__m128` 的参数被分成两半。低有效位部分属于 **SSE** 类别，高有效位部分属于 **SSEUP** 类别。
- 类型为 `__m256` 的参数被分成四个八字节块。最低有效的一个属于 **SSE** 类别，其余属于 **SSEUP** 类别。
- 类型为 `__m512` 的参数被分成八个八字节块。最低有效的一个属于 **SSE** 类别，其余属于 **SSEUP** 类别。
- 类型为 `long double` 的参数的 64 位尾数属于 **X87** 类别，16 位指数加上 6 字节填充属于 **X87UP** 类别。
- 类型为 `__int128` 的参数提供与 INTEGER 相同的操作，但它们无法放入一个通用寄存器，而需要两个寄存器。出于分类目的，`__int128` 被视为按如下方式实现：
```c
typedef struct {long low,high;} __int128;
```
  但存储在内存中的 `__int128` 类型参数必须在 16 字节边界上对齐。
- 类型为 `_BitInt(N)` 且 N <= 64 的参数属于 **INTEGER** 类别。
- 类型为 `_BitInt(N)` 且 N > 64 的参数按其实现为 64 位整数字段结构的方式进行分类。
- 复数类型 `complex T`（其中 T 为 `_Float16`、`float`、`double` 或 `__float128` 之一）的参数被视为按如下方式实现：
```c
struct complexT {T real;T imag;};
```
- 类型为 `complex long double` 的变量被归类为 **COMPLEX_X87** 类型。

聚合类型（结构和数组）和联合类型的分类方式如下：

1. 如果对象的大小超过八个八字节，或者包含未对齐的字段，则其类别为 **MEMORY**¹⁵。
2. 如果 C++ 对象对于调用而言是非平凡的（non-trivial），如 C++ ABI¹⁶ 所规定，则通过不可见引用传递（对象在参数列表中被替换为一个属于 **INTEGER** 类别的指针）¹⁷。
3. 如果聚合类型的大小超过一个八字节，则每个八字节分别分类。每个八字节初始化为 **NO_CLASS** 类别。
4. 对象的每个字段递归分类，每次考虑两个字段¹⁸。根据八字节中字段的类别计算结果类别：
   - (a) 如果两个类别相等，则结果类别即为该类别。
   - (b) 如果其中一个类别是 **NO_CLASS**，则结果类别为另一个类别。
   - (c) 如果其中一个类别是 **MEMORY**，则结果为 **MEMORY** 类别。
   - (d) 如果其中一个类别是 **INTEGER**，则结果为 **INTEGER**。
   - (e) 如果其中一个类别是 **X87**、**X87UP**、**COMPLEX_X87**，则使用 **MEMORY** 作为类别。
   - (f) 否则使用 **SSE** 类别。
5. 然后进行合并后清理：
   - (a) 如果其中一个类别是 **MEMORY**，则整个参数在内存中传递。
   - (b) 如果 **X87UP** 前面不是 **X87**，则整个参数在内存中传递。
   - (c) 如果聚合类型的大小超过两个八字节，且第一个八字节不是 **SSE**，或任何其他八字节不是 **SSEUP**，则整个参数在内存中传递。
   - (d) 如果 **SSEUP** 前面不是 **SSE** 或 **SSEUP**，则将其转换为 **SSE**。

#### 传递

参数分类完成后，寄存器按从左到右的顺序分配用于传递，规则如下：

1. 如果类别是 **MEMORY**，则在栈上传递参数，地址需尊重参数的对齐要求（可能超过其自然对齐）。
2. 如果类别是 **INTEGER**，使用序列 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8` 和 `%r9` 中的下一个可用寄存器¹⁹。
3. 如果类别是 **SSE**，使用下一个可用的向量寄存器，寄存器按 `%xmm0` 到 `%xmm7` 的顺序取用。
4. 如果类别是 **SSEUP**，该八字节在上一个使用的向量寄存器的下一个可用八字节块中传递。
5. 如果类别是 **X87**、**X87UP** 或 **COMPLEX_X87**，则在内存中传递。

当 **INTEGER** 类别的类型的值在寄存器或栈中返回或传递时，超出该类型内存表示中不存在的位（见图 3.1）是未指定的²⁰。

如果参数的任何八字节都没有可用寄存器，则整个参数在栈上传递。如果已经为该参数的某些八字节分配了寄存器，则这些分配将被撤销。

寄存器分配完成后，在内存中传递的参数按相反（从右到左²¹）顺序压入栈中。

对于可能调用使用 varargs 或 stdargs 的函数的调用（无原型调用或声明中包含省略号 `(...)` 的函数调用），`%al`²² 用作隐藏参数来指定使用的向量寄存器数量。`%al` 的内容不需要与寄存器数量完全匹配，但必须是使用的向量寄存器数量的上限，范围为 0–8（含）。

当向使用 varargs 或 stdarg 的函数传递 `__m256` 或 `__m512` 参数时，必须提供函数原型。否则，运行时行为未定义。

#### 返回值

返回值按照以下算法进行：

1. 使用分类算法对返回类型进行分类。
2. 如果类型类别为 **MEMORY**，则调用者为返回值提供空间，并将该存储的地址在 `%rdi` 中传递，就好像它是函数的第一个参数一样。实际上，该地址成为一个“隐藏”的第一个参数。此存储不得与通过此参数以外的其他名称对被调用者可见的任何数据重叠。返回时，`%rax` 将包含调用者通过 `%rdi` 传入的地址。
3. 如果类别是 **INTEGER**，使用序列 `%rax`、`%rdx` 中的下一个可用寄存器。
4. 如果类别是 **SSE**，使用序列 `%xmm0`、`%xmm1` 中的下一个可用向量寄存器。
5. 如果类别是 **SSEUP**，该八字节在上一个使用的向量寄存器的下一个可用八字节块中返回。
6. 如果类别是 **X87**，该值在 X87 栈上的 `%st0` 中作为 80 位 x87 数字返回。
7. 如果类别是 **X87UP**，该值与前面的 X87 值一起在 `%st0` 中返回。
8. 如果类别是 **COMPLEX_X87**，值的实部在 `%st0` 中返回，虚部在 `%st1` 中返回。
